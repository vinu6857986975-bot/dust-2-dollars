=== PAGE 1 ===
CONSTRUCT-AI
Complete Frontend + Backend + Agentic AI File Specification for Antigravity
Purpose: Use this document as the master specification when generating the project in Antigravity. It defines the folder
structure, file names, responsibilities, APIs, database entities, agents, tools, workflow, environment variables, and
implementation order.
Important MVP boundary
The system must not claim that one ordinary house photograph can accurately determine engineering quantities. The
MVP should accept a construction image/floor plan plus user-supplied dimensions. Computer vision identifies visible
structural elements; deterministic Python calculation tools perform quantity estimation; supplier prices come from the
database; the verification agent checks outputs; human approval is required before procurement actions.

<b>intent_agent.py</b> — Converts user request into a structured goal and constraints.
<b>vision_agent.py</b> — Analyzes image/floor plan and returns detected structural information with confidence.
<b>estimation_agent.py</b> — Chooses required calculation tools and combines dimension inputs with construction
assumptions.
<b>material_agent.py</b> — Maps calculated requirements to standardized materials and units.
<b>cost_agent.py</b> — Retrieves reference/supplier prices and calculates totals using deterministic tools.
<b>supplier_agent.py</b> — Searches and ranks suppliers by price, stock, distance and rating.
<b>planning_agent.py</b> — Builds staged material procurement plan.
<b>delivery_agent.py</b> — Creates a delivery plan using supplier location, quantities and timing.
<b>procurement_agent.py</b> — Creates a quotation/order draft; never submits a purchase without approval.
<b>verification_agent.py</b> — Checks calculations, units, missing data, inventory, prices and contradictions. Sends
failures back to orchestrator.

7. End-to-End Agent Workflow
 1. User creates project and enters location, building type and dimensions.
2. User uploads construction image/floor plan.
3. Intent Agent creates structured goal.
4. Orchestrator creates execution plan.
5. Vision Agent analyzes the image and returns detected elements + confidence.
6. Orchestrator checks whether required dimensions are available.
7. If missing, system asks user for the missing dimensions.
8. Estimation Agent calls deterministic quantity tools.
9. Material Agent normalizes the output.
10. Cost Agent obtains reference/supplier prices.
11. Supplier Agent searches and ranks suppliers.
12. Planning Agent creates staged procurement plan.
13. Delivery Agent creates delivery schedule.
14. Verification Agent validates all intermediate/final results.
15. If verification fails, Orchestrator identifies the failed step and replans.
16. If verification passes, show complete recommendation.
17. User reviews and approves.
18. Procurement Agent creates the final procurement draft.
19. Agent log is stored for audit/demo.

3. Agent orchestration: LangGraph/stateful workflow.
4. Implement specialized agents: Intent, Vision, Estimation, Material, Cost, Supplier, Planning, Delivery, Procurement, Verification.
5. Implement deterministic calculation tools. Never ask the LLM to invent engineering quantities or prices.
6. Use uploaded image/floor plan + user-supplied dimensions for the MVP.
7. Build a visible Agent Activity panel showing agent status, actions, timestamps and verification.
8. Add human approval before procurement.
9. Add agent logs/audit trail.
10. Seed realistic demo suppliers/materials/inventory.
11. Provide mock/fallback provider adapters so the application can run without paid AI APIs during development.
12. Include validation, error handling, loading states and empty states.
13. Include API documentation and README with exact setup commands.

16. Development Order

(5) dimension input, (6) calculation engine, (7) Vision Agent adapter, (8) Orchestrator workflow, (9)

17. Critical Design Rules
 LLM plans and reasons; tools calculate.
 Prices come from databases/APIs, not hallucinated LLM knowledge.
 Engineering quantities are preliminary estimates and must be reviewed by a qualified professional before actual
construction.
 One ordinary photo is not treated as a precise dimensional measurement source.
 Procurement is draft-first and approval-gated.
 Every agent action is logged.
 Verification can reject a plan and trigger replanning.
 External API failures have mock/fallback behavior for the student demo.
 Never expose secret API keys in frontend code.
